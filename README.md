# Disk Explorer

一个用来「一层层点进去看目录占用」的小工具：输入路径，服务端测量该目录下每个子项
的大小（**面积/条长 = 占用**），边测边推给页面，浏览器里实时出图。

两种视图，随时切换：

| 视图 | 长什么样 | 适合 |
| --- | --- | --- |
| **矩形树图** | SpaceSniffer / WinDirStat 那种嵌套矩形，面积正比于大小 | 一眼看出谁最占地方 |
| **目录树** | `ncdu` / `tree -du` 那种缩进列表，逐层展开，每行带占比条 | 顺着路径往下钻、比较同级目录 |

是 `home_disk_treemap.py` 那类静态出图脚本的交互版：不用反复跑脚本、改数据、
重新出图。

## 快速开始

```bash
cd ~/workspace/0_Tool/disk_explorer
python3 disk_explorer.py --port 8765
```

然后打开 <http://localhost:8765/>。默认落在**你的家目录**（即 `--allow-root` 指向的目录）。

只用 Python 标准库，**不需要装任何依赖**（Python 3.9+）。

### 在集群上通过 SSH 端口转发访问

```bash
ssh -N -L 8765:localhost:8765 <user>@<login-node>
```

后台常驻：

```bash
nohup python3 disk_explorer.py --port 8765 > /tmp/disk_explorer.log 2>&1 &
```

## 用法

| 操作 | 说明 |
| --- | --- |
| 顶部输入框 | 输入任意路径（支持 `~`），回车或点「扫描」 |
| 矩形树图 / 目录树 | 切换视图，选择会记住（localStorage） |
| 点击色块 | 进入该子目录 |
| 目录树·单击行 | 展开 / 折叠该目录（可同时展开多个，各自独立流式测量） |
| 目录树·双击行 | 把该目录设为根 |
| 目录树·「按大小 / 按名称」 | 切换同级排序 |
| 面包屑 | 从家目录开始逐级展开，点任意一级跳回 |
| ⌂ 家目录 | 一键回到允许浏览的根目录（路径非法时的兜底出口） |
| 悬停 | 完整路径、大小、占当前目录比例、链接目标 |
| `Backspace` | 返回上一级（已在根目录时自动禁用） |
| `R` | 重新测量当前目录（忽略缓存） |
| 「自动刷新」 | 每轮测量结束后等 8 秒再测一次，用于观察正在写入的目录 |
| 点击报错面板 | 关掉提示，回到可交互状态 |

配色约定：**实色 = 目录，浅色 = 文件，白色虚线框 = 符号链接**。
目录树里链接会额外标注 `符号链接` / `链接失效` / `链接→范围外`。

## 大小是怎么算出来的（重要）

### 符号链接：不跟随，不重复计算

所有 `du` 调用都带 `-P`，**永不解引用符号链接**。所以：

- 一个指向 100 GB 目录的软链接，在本工具里算 **0**，而不是 100 GB
- 同一个真实目录被多处软链接引用，也**只会在真实位置被算一次**
- 链接指向的范围外目录无法进入，页面会标 `链接→范围外`；悬停可看到它的目标路径

实测（一个目录里放 32 MB 真实数据 + 4 个软链接，其中两个指向外部）：

```
real          32.0 MB
alias_dir      0.0 MB   <- 补零
alias_file     0.0 MB   <- 补零
dangling       0.0 MB   <- 补零
outside        0.0 MB   <- 补零
total 32.0 MB
```

### 硬链接：整层一次扫描，算一次

这一条是**改动过的**。原本的实现是「每个子项单独跑一个 `du`，并行」，
那样每个 `du` 进程看不到别的进程已经算过哪些 inode，**同一个文件被硬链接到
两个兄弟目录时会被算两遍**。这台机器上硬链接很普遍（`00_LLM` 里抽样 3000 个
文件有 1420 个 `nlink > 1`，conda 的 `pkgs`/`envs` 就是典型），所以偏差不可忽略。

现在默认 `dedup` 模式：**整层用一次 `du --max-depth=1`**，由它统一去重。

实测（同一个文件硬链接到 `a/` 和 `b/`，真实占用 64 MB）：

```
dedup    (新，默认) : 各子项合计 64 MB   du 汇总 64 MB   ✅
parallel (旧行为)   : 各子项合计 128 MB  du 汇总 128 MB  ❌ 翻倍
```

`du -s hard` 自己给的是 64 MB，而 `du -s hard/a` 和 `du -s hard/b` 各给 64 MB
——这正是逐子项测量会翻倍的原因。

单次扫描仍然是**流式**的：`du` 每测完一个子目录就吐一行，页面随之长大重排
（实测 `00_LLM` 的 15 条结果分布在 0–32.6 s 全程到达），所以不会退化成"等半天再出图"。

> 想要快而不是准？加 `--measure parallel` 恢复旧的逐子项并行；子项数超过
> `--bulk-threshold` 时它也会自动退回单次扫描。

### 实时出图

1. `os.scandir` **立刻**返回子项列表（毫秒级），页面先画占位色块 / 空行
2. 后台一次 `du` 流式测量整层，每完成一个子项就通过 NDJSON（chunked HTTP）推给浏览器
3. 结果按「目录路径 + mtime」整层缓存，来回点、重复访问秒开

## 参数

```
--host                 监听地址，默认 127.0.0.1
--port                 监听端口，默认 8765
--allow-root DIR       允许浏览的根目录，可重复指定，默认 $HOME
--measure {dedup,parallel}
                       dedup(默认)：整层一次 du，硬链接只算一次
                       parallel  ：每个子项一个 du，更快但硬链接会重复计数
--workers N            parallel 模式下的并发 du 进程数，默认 min(16, CPU 数)
--bulk-threshold N     parallel 模式下子项超过 N 个时自动退回单次扫描，默认 400
--cache-ttl 秒         缓存有效期，默认 300，设 0 表示不过期
--verbose              打印每个请求
```

> **安全提示**：默认只允许浏览 `$HOME` 以内的路径，避免端口转发出去以后整个
> 文件系统都能被翻。要看别的地方就显式加 `--allow-root /some/path`。

不会把同一层扫两遍。

## 自检

```bash
node test_frontend.js
```

覆盖三类断言：树图布局的铺满率 / 无重叠 / **面积严格正比于大小**；面包屑根目录
落在允许范围内；目录树的展开与折叠行为。期望全部 `ok`。

## 已知限制

- 单次 `du` 扫描是单进程的，比并行方式慢一些（实测 `00_LLM` 约 32 s vs 12 s），
  换来的是硬链接计数正确；重复访问有缓存。
- 目录 mtime 不随深层文件的内容变化而更新，所以「自动刷新」用 `refresh=1`
  绕过缓存，代价是要重新跑 `du`。
- 硬链接只在**同一层内**去重。若两个不同分支共享文件，分别进入两层看时各自
  都会被完整计一次——这与 `du` 单独统计某个目录时的行为一致。
- 超过 500 个子项时，色块/行会把最小的那些合并成「（其余 N 项）」，避免碎裂；
  数据本身不丢。
